# Final Publication Pack: Meta-Agent Audit

Run date: 2026-07-14
Scope: book-level, all seven passes in order.

## Governing finding: the book is a skeleton, not a finished manuscript

The publication pack is designed to run over a fully built book. This book is not
yet built. Of 72 chapters (modules) across 14 parts, exactly one (Module 1, "What
Is Sensory AI?") has authored section files: 8 richly written, conformant sections.
The other 71 chapters exist only as auto-generated placeholder index stubs that
carry the note "Placeholder chapter page. Sections are produced by the book-skills
pipeline." There are 8 section files in the whole repository.

Every pass below was executed against what actually exists. Passes that target
section content therefore acted on 8 files; passes that target chapter index pages
saw 71 unbuilt stubs. The single most important recommendation for the next run is
to gate this pack behind a completeness check (all planned sections built) so it is
not run prematurely again.

## Per-pass results

### Pass 1: Deduplication
- `scripts/detect_duplicates.py` did not exist; it was created and run.
- 8 sections, 473 text blocks scanned; 60 candidate pairs at similarity >= 0.55.
- After review: 0 genuine content duplications. All 60 pairs are (a) shared
  boilerplate (the footer line, the prerequisites block) or (b) shared callout
  label prefixes ("Real-World Application:", "In Practice:", "Try It:",
  "Step-Through:") on substantively different examples (commercial aviation vs
  autonomous driving vs consumer wearables). The one prose-level pair (the
  x = h(s) + eta inverse-problem question in 1.1 self-check and 1.2 deeper prompt)
  is intentional depth reinforcement.
- Resolution for every pair: SKIP. No edits made.

### Pass 2: Structural Review
- Section naming is uniform (`section-1.N.html`, H1 equals the section title,
  part-label and chapter-label present).
- No module index lists fewer than 3 planned sections (checked all 72).
- All 8 built sections have a "What's Next" block; 1.1 through 1.7 link to the next
  section, 1.8 links to Chapter 2. All targets resolve.
- Structural anomaly (not fixable by a publication pass): 71 of 72 chapters have 0
  built sections. This is unbuilt content, not malformed structure; it requires the
  content pipeline, not this pack.

### Pass 3: Epigraph
- Design intent confirmed: `templates/chapter-index.html` includes an epigraph
  block, so built chapter index pages should carry one.
- 71 of 72 module index pages lack an epigraph, but all 71 are minimal placeholder
  stubs that also lack the rest of the chapter-index template (illustration,
  overview, objectives, big-picture, bibliography). Bolting a fabricated epigraph
  onto a stub that the book-skills pipeline will regenerate from the template is
  premature churn that would be discarded on the next build.
- Action taken: added a thematic, in-voice epigraph to the one chapter with built
  content, Module 1's index page, bringing its landing page into line with its 8
  built sections. The remaining 71 are deferred to chapter build time.

### Pass 4: Bibliography
- One built section carries a bibliography (section 1.8); it is the only place the
  pass applies.
- All 10 entries have author(s), year, title, and venue. No truncated entries, no
  "..." endings, no duplicates. Every entry links to a resolvable DOI or publisher
  or arXiv URL.
- The pass's "sort by year descending" rule was NOT applied: the bibliography is
  deliberately organized into three thematic categories ("Foundations", "Represen-
  tation learning and foundation models", "Uncertainty, evaluation, and the running
  threads") with per-entry annotations. A global year sort would destroy that
  designed structure and the Kalman-1960-first framing. Categorized-with-annotation
  is the book's bibliography style; entries are complete and de-duplicated, which is
  the substance of the check. Flagged as an intentional deviation, not a defect.

### Pass 5: Controller Sweep
- Sampled across the 8 built sections (the population is smaller than a 10-section
  stride, so all were covered).
- No em dashes and no prose double-hyphens anywhere. The only "--" occurrences are
  legitimate HTML comments in the 1.5 SVG source.
- No syllabus language. Two "graded" regex hits are false positives: one is inside
  "degraded" (a sensor-health term), the other is metaphorical capstone framing.
- All 11 callout classes in use (big-picture, key-insight, practical-example,
  research-frontier, library-shortcut, self-check, fun-note, warning, tip, exercise,
  lab) are valid book types.
- Cross-reference links all resolve.

### Pass 6: Publication QA
- All 8 section files: `<title>` matches the H1 heading; every `<img src>` resolves
  (7 figures present, section 1.7 has none by design); CSS link is
  `../../styles/book.css`; footer nav present; no broken `</html>`.
- 155 relative links checked across the 8 sections; the only non-resolving targets
  are the vendor KaTeX/Prism CSS/JS assets, which are intentionally gitignored
  (installed locally per `vendor/README.md`). Not a defect.

### Pass 7: Meta-Agent Audit (this file)

## Underperformers and prompt-sharpening recommendations

Because only one chapter is built, "underperformance" is measured against the built
content and against the pack design, not against 72 chapters of diff.

1. Pack with most skipped tasks: **Pass 3 (Epigraph)**. 71 of 72 targeted pages were
   deferred rather than edited. Root cause is not agent failure; it is a scope
   mismatch (the pack ran before chapters were built). Prompt fix: add a precondition
   to Pass 3, "only act on chapter index pages that already follow the full
   chapter-index template (epigraph slot, overview, objectives). Skip auto-generated
   placeholder stubs and report their count; do not fabricate epigraphs onto pages
   the content pipeline will regenerate."

2. Pack with most edits per section (over-engineering risk): **Pass 1 (Dedup)** as
   specified. A raw 0.55 threshold over all block-level text flags 60 pairs in a
   single clean chapter, effectively all noise from shared footers and callout label
   prefixes. Left unqualified, an agent could "fix" (rewrite) genuinely distinct
   examples that merely share a label. Prompt fix: "before computing similarity,
   strip structural boilerplate (footer, prerequisites) and the leading callout-label
   prefix from each block; treat pairs whose only overlap is a shared label prefix or
   a shared equation as SKIP; require a reviewer to confirm >= 2 consecutive shared
   sentences of body prose before any MERGE or CONSOLIDATE."

3. Cross-cutting fix for the whole pack: prepend a gate. "Count built section files
   vs planned sections. If more than a small fraction of chapters are unbuilt
   placeholder stubs, stop and report that the book is not ready for a publication
   pack rather than running content passes against stubs."
